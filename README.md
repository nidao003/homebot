# fengshui-bagua · 八宅定盘工具包

> 东方命理「八宅」传统经验体系的**开源实现**：立极 → 八分法 → 房间归宫 → 星曜判定 → 出图。
> 纯前端 / 纯标准库，**无后端、无网络请求、零隐私**。

![style](https://img.shields.io/badge/python-3.8%2B-blue) ![deps](https://img.shields.io/badge/dependencies-none-green)

---

## 这是什么

给定一张户型平面图和几项参数，输出每个房间落在**八宫**中的哪一宫，以及该宫在各套体系下的**星曜**（吉凶）。

两个交付形态：

| 形态 | 位置 | 特点 |
|------|------|------|
| **网页工作台** | `src/web/index.html` | 单文件，浏览器直接打开即用。图片**只在本机内存里处理，不上传**。可导出 PNG / SVG / JSON |
| **Python 库 + CLI** | `src/bagua/` | 无第三方依赖。配置驱动，可脚本化批量出图 |

## 快速开始

### 网页版

```bash
# 任选其一
open src/web/index.html              # 直接双击也行（file:// 也能跑）
python3 -m http.server 5183          # 或起个本地服务
```

打开后：

1. **载入户型图**（可选）—— 图片只在浏览器本地读取，不发任何网络请求
2. **画房间** —— 在图上逐点单击，双击闭合，填名称
3. **设立极** —— 点一下建筑主结构的太极点
4. **调立极框** —— 框住主结构外接矩形（阳台 / 挑板通常不计入）
5. **调正北** —— 拖罗盘或滑块，让「图像正上方」对应到真实方位角
6. **定宅卦 / 门位 / 命卦** —— 选好伏位宫
7. **导出** —— PNG 出图、SVG 出矢量、JSON 存配置、打印出纸

内置「载入示例」按钮会生成一套**完全虚构**的示例户型，方便先看效果。

### Python

```bash
cd fengshui-bagua
PYTHONPATH=src python3 -m bagua.cli demo -o demo.svg
PYTHONPATH=src python3 -m bagua.cli render examples/sample_house.json -o out.svg --json out.json
PYTHONPATH=src python3 -m bagua.cli stars      # 打印八宅星曜表
```

```python
import sys; sys.path.insert(0, "src")
from bagua import analyze

report = analyze({
    "site": {
        "center_px": [500, 500],       # 立极中心（图像像素）
        "north_deg": 0,                # 图像正上方对应的真实方位角
        "bounds_px": [200, 200, 800, 800],  # 立极矩形
        "home_palace": 6,              # 宅卦（伏位宫）
        "door_palace": 8,              # 门位（伏位宫），可省
        "minggu": [{"name": "甲", "palace": 9}],
    },
    "rooms": [
        {"id": "r1", "name": "客厅", "poly": [[560, 210], [790, 210], [790, 330], [560, 330]]},
    ],
})
print(report["rooms"][0]["palace_name"], report["rooms"][0]["home_star"])
```

## 三套口径，不可混用

同一张星曜表，三种「伏位」定义。这是本项目最容易出错的地方：

| 口径 | 伏位 = | 用途 |
|------|--------|------|
| **宅卦**（八宅） | 坐山宫 | 看一套房子本身的整体格局 |
| **门位**（大游年） | 大门所在宫 | 看动线、内外气口 |
| **命卦** | 命卦宫（东四命／西四命） | 看某个人的用神落位 |

东四命 = 坎离震巽；西四命 = 乾坤艮兑。报告里三个口径**分列呈现**，不合并成一个结论。

## 算法说明

### 立极

建筑主结构的中心太极点。**立极框**取主结构的外接矩形；阳台、雨棚、挑板等悬挑构件通常不计入 —— 计入会平移重心，进而改变所有宫的判定。

### 八分法（米字格）

以立极中心为太极点，连接中心与立极矩形的**四角**和**四边中点**，得到 8 个方向区，每个区含一角 + 相邻半条边。经典做法。

### 方位角

```
真方位角 = theta0 + atan2(dx, -dy)      # 图像 y 向下
theta0   = 图像「正上方」对应的真实方位角
```

注意：很多户型图上标的「N 朝上」是错的（尤其 CAD 导出图）。真实朝向要看**主采光窗**和**外立面**。请务必人工确认 `north_deg`。

### 归宫

1. 用 Sutherland–Hodgman 把每个房间多边形裁剪到 8 个方向区，算重叠面积
2. 取重叠面积最大的方向区
3. 若该区占比 < `SPLIT_THRESHOLD`（0.45），判为**跨宫**，改用房间**重心**所在方位定宫，并在图上标注

纯重心法对边界房很敏感（一个跨两条线的长条房，重心可能落在完全无关的角上）；纯重叠法对凸形房又偏保守。所以用混合判定。

### 两种归宫方法的差异

`method` 字段可选：

- `grid` —— 米字格八分法（需 `bounds_px`）。**推荐**
- `wedge` —— 以中心切 45° 扇形（只需中心）。仅在朝向正好是南北时可靠

详细讨论与真实案例回归见 [`docs/algorithm.md`](docs/algorithm.md)。

## 配置格式

```jsonc
{
  "site": {
    "center_px": [500, 500],            // [x, y] 图像像素
    "north_deg": 0,                     // 图像正上方 = 真实方位角(度)
    "bounds_px": [200, 200, 800, 800],  // 立极矩形 x0,y0,x1,y1
    "home_palace": 6,                   // 宅卦：1坎 2坤 3震 4巽 6乾 7兑 8艮 9离
    "door_palace": 8,                   // 门位（可省）
    "minggu": [                         // 命卦（可省/多条）
      {"name": "甲", "palace": 9}
    ],
    "method": "grid"                    // "grid" | "wedge"
  },
  "rooms": [
    {
      "id": "r1",
      "name": "客厅",
      "poly": [[560, 210], [790, 210], [790, 330], [560, 330]],
      "area": "12.5㎡",                  // 可选
      "notes": ["主采光窗在此"]           // 可选
    }
  ],
  "meta": { "title": "示例" }            // 可选
}
```

`poly` 用图像原始像素坐标（不是缩放后的画布坐标）。

## 隐私

**本项目不收集、不上传、不外传任何数据。**

- 网页版是**纯静态单文件**，所有图像处理在浏览器本地完成，**没有 fetch、没有后端、没有分析脚本**
- 户型图只在内存里，不落盘、不外传
- 仓库内**不含任何真实住户信息、真实户型图、真实地址、真实命卦**
- `examples/` 里是**完全虚构**的示例数据
- 导出的 JSON / SVG 只含你自己填的字段

自己部署时也请注意：别把真实户型图和截图放进仓库；仓库自带的 `.gitignore` 已排除常见误提交路径。
